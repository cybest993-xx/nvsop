## 5.5 预览与录像（与 GPU 完全无关）

**海康 RTSP 地址格式**（已查证）：

```
主码流（判定用）: rtsp://<user>:<pass>@<ip>:554/Streaming/Channels/101
子码流（预览用）: rtsp://<user>:<pass>@<ip>:554/Streaming/Channels/102
```

注意事项（已查证）：密码含特殊字符必须 URL 编码（`@`→`%40`、`:`→`%3A`）；经 NVR 接入时通道号由 NVR 分配、不是 1；子码流特性是低码率、延迟稳定。

**⚠️ 拿到真机后必须首验**：子码流实际编码与 profile（`ffprobe` 看 `has_b_frames`）。WebRTC 不支持 B 帧（§2.11）——若子码流带 B 帧，先按具体型号能力尝试在摄像机 Web 配置中调整 codec/profile/GOP；**能关闭不兼容编码是零转码方案成立的前提**。配不掉才对该路启 x264enc 转码并在界面标注额外 CPU 开销。

```
相机主码流(101) ──→ 推理机推理服务容器（判定，GPU）
相机子码流(102) ──→ MediaMTX（每路配置 passthrough 或 CPU 转码）
                     ├─→ WebRTC 单路详看（浏览器直连）
                     ├─→ WebRTC 多路大屏（浏览器直连，容量须实测）
                     └─→ 分段录像（推理机滚动窗口按主机配置）→ 违规时 ffmpeg -c copy 切片 → 本机证据目录
```

排除推理服务 DeepStream RTSP 输出与 `ENCODE_VIDEO`（§2.9）。

控制面为推理机保存独立的 `mediamtx_playback_address`，相机保存 `media_path_mode`（`passthrough` 或 `cpu_transcode`）和 `recording_mode`（`preview_only` 或 `continuous`）。中心媒体查询生成仅由相机 UUID 派生的稳定 path 和直接地址；按主机导出的 JSON 只包含非秘密拓扑与本机 `credential_files` 引用。部署人员在推理机把它合并到本地媒体策略后应用，MediaMTX 配置由边缘进程生成；凭据文件只读且不进入中心、浏览器或日志。配置保存与本机实际应用分别表达，不凭保存成功声称媒体已运行。

**预览按需不等于录像按需。** `preview_only` 只用于明确未参与 SOP 执行的调试相机，不录像，最后一个观看者离开并到达配置等待期后释放源。参与 SOP 执行的相机必须使用 `continuous`，配置与运行入口都拒绝仅预览组合；无法证明未参与执行时不允许以调试模式绕过。连续模式自本机启用起持续拉流和录像，与观看者数量无关。按需源加录像开关不能替代无人观看时持续录制，不能创建假观看者维持录像。

**单一媒体路径与本机所有权。** 每路只有一份子码流来源；需要转码时一份 CPU H.264 输出同时供预览与录制，不能按观看者重复编码或调用判定 pipeline 的 GPU 编码。窗口、分段和释放时长来自配置。主机、工位或相机停用后停止对应取流与新录制，重启也不恢复；已有分段和回放所需元数据保留。由判定提升出的证据片段与关键帧也留在产生它们的推理机，中心只接收证据身份、来源主机、锚点、窗口、素材代次、摘要、大小和可访问引用。重复应用不产生重复进程/path，失败不冒充生效，保持或恢复上一份有效配置；中心不可达不阻止本地运行或证据落盘。

**窗口缩短先确认。** 生效前按实际分段估算受影响数量、空间和最早/最晚时间，由操作员明确确认；基准配置或目标窗口变化则重新估算。取消、估算失败或过期确认保持原窗口。新值只进入后续正常回收，不同步批量删除，不越过录像目录清理 SQLite、上报或证据队列。该基础滚动窗口流程不替代 §5.19 的分类保留和引用保护。

**浏览器播放与业务判定分离。** 媒体描述和编辑沿用 `device` 的查看/编辑权限、会话、CSRF 与 revision 契约；Web 不自行关联全厂拓扑、推测回放端口或携带中心凭证直连媒体。真实可解码首帧才表示播放成功，每路连接、首帧等待和重试有终点，另提供手动重试。停止、切换、离页或已知权限撤销释放连接、请求和重试，迟到结果不能复活播放器；中心普通断网不等于撤权，不主动中断已建立直连。回放以实际区间为准，区别缺口、过期和访问失败，UTC 传输、Asia/Shanghai 展示。媒体错误不生成 SOP 不通过或伪造流健康。

生产直连沿用可信工厂网络/VLAN 与端口控制，不新增逐观看者 JWT、JWKS 或中心回调。信令与回放须适配 HTTPS 页面，证书可信、CORS 限定 Web origin，不绕过证书或混合内容限制；本地可直达时不依赖公网 STUN/TURN。中心 RBAC 不宣称能吊销绕过 Web 的同网段媒体连接。管理员接口/发布入口限受控网络，设备秘密只留在本机，配置不能当 shell 命令执行。

这些边界的实现来源是 [`device` 媒体用例](../../../apps/control-api/src/factory_sop/device/usecases/media.py)、[本机媒体运行时](../../../apps/edge-runtime/src/edge_runtime/media.py)和[配置应用脚本](../../../scripts/apply_media_export.py)。运行步骤、原 #34 软件验收与后置验证追溯见[媒体部署说明](../../../deploy/media/README.md)。部署与测试的存在不表示每条验收或现场容量已通过。

**录像磁盘容量**：`子码流码率 × 路数 × 配置的滚动窗口秒数 × 1.3`。余量系数覆盖 VBR 峰值、文件系统开销与"不跑满盘"三项，**算例必须含它**。下表仍用 7 天作为示例参数，不是代码默认值或不可变上限；部署时必须按实际配置复算。按 1 Mbps 估算（1 Mbps × 604800 s = 75.6 GB 裸容量，×1.3 后）：

| 路数 | 裸容量 | 含余量（按此备料） |
|---|---|---|
| 1 | 75.6 GB | **~98 GB** |
| 8 | 605 GB | **~786 GB** |
| 50 | 3.78 TB | **~4.9 TB** |

这是推理机的硬件清单项，须在 C4 门禁前按实际码率和配置窗口复算。子码流实际码率高于 1 Mbps 时按比例放大。**压缩归档的节省不预先计入**（§5.19）：压缩比须在目标子码流上实测后才可写入本表，备料按不压缩计算。压缩带来的余量用于延长可配置的保留期，不用于缩减备料。

## 5.19 数据保留与压缩

**【已定】保留策略可配置，按判定类别分类，由 `retention` 模块拥有策略、由数据拥有者执行删除。**

### 总则：时长一律是配置，代码内不得出现字面量

**本节及全文出现的每一个时长数字都是默认值，不是常量。** 判定核心、supervisor、回收任务、mediamtx 配置生成中都不得出现硬编码的保留时长——包括看似"显然"的 7 天、24 小时、90 天。它们全部经配置解析后作为数据传入（判定核心尤其如此：它不读配置，见 §5.18）。

批准约束是：**回收与切片相关运行时长从配置进入所属 seam，不在业务路径写死保留时长**。当前仓库已有配置接口和行为测试约束已实现路径，并在 `scripts/check_repo_policy.py` 增加了针对**已存在的切片/回收业务路径**的保留/窗口时长字面量检查（`SLICING_RECYCLING_PATHS`：边缘 `media.py`、`media_retention.py`、`evidence_media.py`、`supervisor/evidence.py`）。该检查只覆盖这些已登记路径，且只认名字带保留/窗口语义、值由数字字面量构成的赋值；它**不是**覆盖全部回收/切片代码的仓库级全局时间字面量门禁，不把这一目标描述成已由 ruff 或其他全局检查保证。默认值应集中在所属配置定义里（`factory_sop.retention.model` 与边缘媒体配置），改默认值不是搜索替换业务代码。

首版默认值一览（**全部可改**，均为按工程惯例取的默认值）：

| 项 | 默认 | 归属 |
|---|---|---|
| 录像滚动窗口 | 7 天 | 推理机 |
| 录像压缩起始年龄（= 原始素材窗口） | 24 小时 | 推理机（边缘媒体配置 `recording_compression_age_seconds`） |
| 证据保留：通过类 | 90 天 | 全局默认，工位可覆盖 |
| 证据保留：不通过类 | 永久 | 同上 |
| 证据保留：不可判定类 | 90 天 | 同上 |
| 观测/判定明细保留 | 90 天后聚合归档 | 全局默认 |
| 记录压缩起始年龄 | 7 天 | 全局默认 |
| 违规与处置记录 | 永久 | 全局默认 |
| 推理机本地已上报数据 | **14 天** | 全局默认 |
| 片段窗口前/后余量 | 5 s / 5 s | 全局默认，工位可覆盖（§5.20）|

"永久"是一个显式可选值，不是"没设置"。界面必须能区分二者。

**推理机本地 14 天的取值理由**：这个期限只约束已经成功上报、中心已有权威镜像的结构化本地状态；14 天覆盖"周五坏、周一修"那一类中心离线，并留出发现积压的余量。它**不适用于证据媒体**：中心只有证据引用而没有媒体副本，证据文件按证据保留类别和引用保护在推理机本地管理。备份范围与恢复语义仍待 Q36 裁决（见方案 §四），不能因为元数据已在中心就假设本地媒体可丢。**待上报结构化事实与待登记证据元数据的队列不受此期限约束**；队列项只有在中心确认相应事实/引用后才可完成，但证据文件本身仍由本地证据保留策略决定何时删除。

**上限与下限须有校验**：设成 0 或负数、设成超过录像滚动窗口的证据再切片期望、把明细保留期设得短于压缩起始年龄，都是配置错误，保存时即拒绝并说明原因，而不是运行时表现为怪异行为。

### 五类数据面各自的保留语义

| 数据面 | 位置 | 保留由谁执行 | 可配置项 |
|---|---|---|---|
| 连续分段录像 | 推理机 mediamtx | mediamtx 保留策略 + 边缘运行时的压缩归档任务 | 滚动窗口时长（默认 7 天）、是否压缩归档、压缩起始年龄（默认 24 小时）|
| 证据（片段与关键帧） | 产生它的推理机本地证据目录 | 边缘运行时执行；中心 `evidence` 持索引/复核状态 | 按判定类别分别设时长；可设为永久 |
| 观测与判定记录 | 中心 PostgreSQL TimescaleDB hypertable（按 `received_at` 分区；S021 已启用原生压缩） | `monitor` | 明细保留时长、压缩起始年龄、聚合归档年龄 |
| 违规与处置记录 | 中心 PG | `monitor`（ADR-0010） | 保留时长；默认永久 |
| 推理机本地状态 | 推理机 SQLite | 边缘运行时 | 已上报数据的保留时长 |

中心 `evidence` 只登记证据 ID、来源推理机、锚点、窗口、素材代次、sha256、大小、访问引用与复核状态，不持有媒体字节。中心确认的是**引用/元数据已登记**，不是“已经复制到中心”；浏览器复核具体证据时按中心授权定位到拥有该文件的推理机读取。

**当前实现状态（S040–S041）**：`retention` 已作为真实 Center 模块注册，拥有全局保留策略的声明、严格完整组解码、三类证据解析与单行策略持久化/CAS（`retention_policy`）；`auth` 登记 `retention.policy.view/edit`。S041（#204）补齐工位整组覆盖与生效解析：`retention` 拥有每工位的覆盖记录（`retention_station_policy`：整组跟随全局默认或整组自定义的模式、覆盖组与记录版本；没有记录即跟随全局默认），首写用真实 CAS 建立、后续为条件更新，HTTP 面是 `/retention/policy` 与 `/retention/stations/{id}`；`device` 只为该记录提供工位存在与启用事实，`device_station` 不持有任何保留配置；

**缩短前影响估算（S042）**：`retention` 通过全局和工位 `impact-estimate` 入口，逐一比较八个字段的基准与目标，按新暴露窗口 `(参考时刻－基准时长, 参考时刻－目标时长]` 向各 owner 读取真实事实；永久基准没有下界。全局只影响整组跟随全局的工位，自定义整组全部排除。证据类别由 `monitor` 的来源主机、工位、实例三元身份事实和锁存违规共同解析，不用数据面最短阈值替代逐类别估算。返回对象数、拥有者可度量字节、最早/最晚时刻，并将已知引用保护对象与新暴露对象互斥计数；未结案或锁存违规不因处置成功解除保护。缺类别、媒体大小、复核状态或来源事实时，返回明确不完整原因，不能确认相应缩短；尚未持久化的“在审”状态不能默认当作无保护（#206）。压缩/聚合只报告处理范围，节省量未知，不冒称删除对象或物理空间回收。

推理机本地已上报结构化记录由已有独立证据服务提供只读统计，不扫描媒体目录。中心通过 device 的来源清单与最新签发配置身份请求来源机；Edge 必须与本地已确认配置的 revision、`effective_sha256` 和实际基准一致，尚未确认、不可达或任一来源失败都不能按零或部分小计放行。该入口使用独立统计票据和机器签名逐次回查当前会话/权限，不复用媒体授权，不新建队列、缓存或重试。外部统计等待前结束准备读事务并释放数据库连接，返回后在原请求 Session 重新验证、续期会话，重读来源、中心计数和策略基准；等待期间来源或基准变化即拒绝，不重试。策略写入仍只由请求末尾统一提交。统计窗口从中心成功确认的 UTC 时刻起算；单调发送时刻不用于年龄，历史缺确认 UTC 的行保持未知并拒绝相关缩短。SQLite V20 只追加确认时刻列，不回填猜测历史值。字节为 `serialized_rows` 逻辑序列化量，不代表 SQLite 物理回收、压缩节省或本机媒体删除资格。

确认前不写策略，取消不发更新；确认 `PUT` 必须带回估算令牌和 `If-Match`。服务端按原参考时刻重算，摘要绑定完整基准、目标、全局版本、工位模式、自定义排除范围、来源配置和计数；任一变化、不完整、未来参考时刻或过期均拒绝旧确认。有效期由部署显式配置，无业务默认值；缺配置只拒绝缩短，不阻止查看或延长。有效确认仅更新策略/覆盖记录及安全诊断，不同步删除。配置方法见[部署配置](../../deployment/configuration.md#保留影响估算)；引用保护持久状态（#206）、回收执行（#207）与本地裁剪（#208）仍由各自后续票实现。

配置组合把按工位解析后的完整生效组放进 `stations[].retention` 并声明 `retention.station-policy-v1`（兼容边界见[机器契约演进](machine-contract-evolution.md)），Edge 只消费该已解析组，不在边缘重算默认值与覆盖组的合并。录像滚动窗口仍按推理机配置（§5.19、§5.5）。缩短前影响估算（#205）已由上方 S042 段说明；引用保护（#206）与回收执行（#207）仍待各自票实现——本阶段只下发生效组，不执行删除。三类证据时长、记录明细/压缩/聚合年龄、违规与处置、推理机本地已上报数据的默认值集中在 `factory_sop.retention.model`，永久为显式枚举，未设置与不保留互不混同。推理机本地已上报数据裁剪仍由边缘运行时执行。

**当前实现状态（S020/S021）**：`monitor` 的三张镜像事实表（判定、健康、观测）按 `received_at` 分区为 TimescaleDB hypertable，并使用 TimescaleDB 原生 columnstore 与后台压缩作业；压缩起始年龄取 `retention` 已解析的记录压缩年龄，策略组写入时在同一事务中更新三张表的原生作业配置，失败则整次写入回滚。这条跨模块数据库联动由 `retention_policy` 的写入触发器调用 `monitor` 所拥有的受控压缩作业更新函数；若作业缺失则策略更新失败而不伪报成功。作业运行状态和错误可通过 `timescaledb_information.jobs`、`job_stats` 与 `job_errors` 查阅；作业不会删除仍受引用保护的身份/事实记录，记录回收仍由后续独立任务执行。hypertable 的唯一约束必须包含分区列，因此全局 `event_id` 唯一由同模块的普通身份表保留；decision/health 另有全局 `stream_sequence`，事实表用含 `stream_sequence` 的复合外键指向身份表，observation 无流序号、只按 `(event_id, received_at)` 约束；S040 的保留配置归属不变。

**滚动录像不参与分类。** 录制发生在判定之前，做不到"只录某一类"。分类作用于**从滚动录像提升为长期证据**那一步（§5.5 的 `ffmpeg -c copy` 切片），即：哪些判定类别触发提升、提升后留多久。滚动窗口本身对所有路统一。

### 判定类别是三类，不是 OK/NG 两类

保留类别与 §5.2 的三值判定同构：**通过 / 不通过 / 不可判定**。

不可判定必须是独立一类而不能并入任何一边：它是本系统区别于基座的核心能力（§2.1），也是排障价值最高的一类——`不可判定 + STREAM_LOST` 时运维要靠画面判断是网络抖动还是相机故障。把它并入"通过"会丢掉排障依据，并入"不通过"会污染合规统计。

**挂有已锁存违规的实例按"不通过"类保留，无论其实例判定结果为何。** §5.2 已定违规锁存与实例判定相互独立，实例可以是不可判定而同时挂一条已锁存违规；违规是已确认的事实，其证据必须留。

**通过类默认也保留（可配置为不留）。** 合规率需要分母：只留不通过会让"合规率"无法计算，只能得到违规绝对数。选择不留通过类证据的部署要在界面上明确这一后果。

**不可判定类的证据是断点之前的片段。** 断流后没有画面可切，`STREAM_LOST` 的证据就是"录像在该时刻终止"这一事实本身加上终止前的片段。

### 压缩：录像重编码归档，证据不动，记录使用 Timescale 原生压缩

**压缩的对象是录像文件，不是实时检测路径。** 二者的约束完全不同：实时路径受 500 ms 预算与 §2.8 的转码瓶颈约束（8 路软编吃 ~10 核，50 路不可行），归档压缩不在任何延迟预算内、可延迟到低谷时段、可用硬件编解码通路。

| 对象 | 压缩 | 做法与理由 |
|---|---|---|
| **连续分段录像** | **做** | 全系统最大的存储项（§5.5：50 路 7 天约 4.9 TB）。已老化出"原始素材窗口"的分段重编码后原位替换。**编码格式受再切片回看约束，见下** |
| 证据片段与关键帧 | **默认不做** | 完整性优先，见下 |
| 观测/判定/上报记录 | **做** | 三张 `monitor` hypertable 使用 Timescale 原生 columnstore 与按策略年龄运行的后台作业；保留策略不删除事实或身份表记录，回收仍由数据拥有者独立执行 |
| 推理机 SQLite | 不做，只裁剪 | 嵌入式库压缩收益小、复杂度高，直接删更干净 |

**压缩是让保留期可延长的前提。** 这两个需求是一件事：7 天窗口在 50 路下已占 4.9 TB，要延到 30 天就是 21 TB，不压缩则保留期无法配置得更长。压缩省下的容量直接换成可配置的保留时长。

**录像压缩的五条约束**：

1. **延迟于原始素材窗口。** 分段必须先度过一个"原始素材窗口"（默认 24 小时）才可被压缩。该窗口内的证据切片与再切片（§5.20）从**未重编码的原始分段**取，`-c copy` 无损；压缩必须落在其后。
2. **编码格式必须保持浏览器可直接回看。** 归档压缩后的分段仍是再切片的素材来源（§5.20），而再切片产物要在复核界面里播放。**默认用 H.264 提高 CRF 而非换 H.265**：H.265 在 Chrome/Edge 的支持依硬件与平台而异，不可靠；若归档为 H.265，再切片就得再转一次码才能回看，等于三代编码。节省少一些，换取"再切片产物 `-c copy` 即可回看"这条性质。想用 H.265 的部署必须接受再切片时的额外转码，并在界面标注该片段已多代编码。
3. **不得与判定争资源。** 走 NVDEC→NVENC 全硬件通路时，编解码用的是独立于 CUDA 核的硬件单元，与推理争用主要在显存带宽与显存容量上，而非算力。但**这一点尚未在目标 GPU 上实测**，故它是门禁项而非已知事实（见下）。任务必须可限速、可暂停、可中止，且判定侧出现积压时自动让路。
4. **原位替换须先验证后删除。** 重编码产物校验通过（时长一致、可解码、帧数在容差内）才删原分段；失败则保留原文件并告警。中途断电不得同时丢掉两份。
5. **【已定】压缩画质损失可接受，故 CRF 由实测扫出而非保守取值。** 压缩比与耗时是实测值：子码流本来就是低码率，提高 CRF 的实际节省须在真机上按目标子码流实测。既然画质损失已被接受，发布/现场验证中的实测**扫一组 CRF 找到复核可用性开始劣化的那一档，取其前一档为默认值**，而不是测单一保守设置——保守取值会白白丢掉可换成保留期的容量。

   **唯一的下限是功能性的，不是画质指标**：压缩后的分段仍须支撑人工复核判断与再切片（§5.20）。压到看不出发生了什么，再切片这个功能就失去意义，`不可判定 + STREAM_LOST` 也无法用画面区分网络抖动与相机故障（§5.19 分类保留的用途之一）。故验收标准是"复核人能据此下结论"，由人判断，不由 PSNR/SSIM 之类客观指标代替。

   §5.5 的备料表在实测前按**不压缩**计算，压缩节省不预先计入；实测后按 CRF 定档复算，节省用于延长可配置保留期。

**为什么证据默认不重编码**：证据是支撑违规判定的凭据，Q4 保留了 sha256 完整性校验，重编码会改变文件从而使原始摘要失效——"已被确认的事实"的载体被系统自己改写过，在合规追溯上是自伤。且证据切自子码流且 `-c copy`（§5.5），单体本来就小。若某部署的证据总量确实成为瓶颈（长期保留下会累积），可作为显式配置开启，但必须同时记录原始与重编码后两个摘要并在记录上标注"已重编码"，不能静默替换。这条留到有真实容量压力时再定，现在不做。

### 变更保留策略是破坏性操作

- **缩短保留期只对将来生效**，不立即批量删除历史数据；各数据拥有者按新策略逐步执行，可观察进度。证据媒体的实际删除发生在拥有文件的推理机，不由中心直接删媒体文件。
- **提交前必须显示影响**：将删除多少记录/文件、占多少空间、最早与最晚时间范围。不显示影响的确认按钮等于让人盲签。
- **不得删除仍被引用的数据**：仍关联开放违规、在审复核或未结案 SOP 实例的证据一律保护，不因保留期到期而删。中心 `retention` / `evidence` 负责计算并下发可删除/受保护事实，边缘运行时在实际删文件时再次以当前同步状态执行该约束；未知或失配状态不能当作无人引用。
- 策略变更产生诊断日志事件，记录操作人、变更前后值与影响估算。
- **与备份的关系必须显式**（关联 Q36）：中心记录、中心训练素材卷与推理机本地证据媒体是不同备份对象；备份保留期长于在线保留期时，删除只是"在线不可见"而非真正删除。二者的关系要在界面上写明，不能让运维以为数据已彻底删除。

### 策略的粒度

**全局默认 + 工位覆盖，覆盖为整组替换**，与运行参数同一模式（§5.3）：工位要么整组跟随全局默认，要么整组自定义。理由相同——逐项合并要在中心与界面各写一套合并与来源标注规则，收益不足；而"这个工位的保留策略是什么"必须一眼可答。

录像滚动窗口是**例外，按推理机配置**：它受该机磁盘容量约束（§5.5 容量公式），而磁盘是主机属性，不是工位属性。

### 磁盘水位是安全问题，不只是运维问题

§5.7 已识别推理机自评健康的自指问题，并明确举例"磁盘满导致 `local_report_queue` 写入失败而判定输入链路表面正常"。保留策略是这个风险的第一道防线，但不是全部：

- **待上报队列与待登记证据元数据队列永不因空间回收而删除**；证据媒体本身也是推理机上的权威文件，未满足证据保留/引用保护删除条件时不得靠磁盘压力丢弃。
- 磁盘水位越过阈值时该路进**不可判定**并显式告警，不静默写失败。这是 §5.2 安全不变量在存储维度的落地：写不下证据就等于观测能力不完整。
- 水位阈值与当前用量在设备管理页可见，与录像容量公式（§5.5）并排显示。

## 5.20 证据片段窗口与再切片

**【已定】片段窗口是可配置的前后余量，锚点由判定核心声明。再切片可用，但受滚动录像窗口限制。**

### 窗口的形状：锚点 + 前后余量

片段不是"从某时刻起 N 秒"，而是**围绕一个语义锚点向前后各留一段余量**。余量是配置项（默认见 §5.19 总则表），全局默认可被工位覆盖。

锚点按违规类型不同，由判定核心随判定输出一并声明（§5.18 已定"判定输出含需要的证据切片区间"）：

| 违规 | 锚点 |
|---|---|
| 错步 | 错误动作被识别的那条观测 |
| 反序 | 打破顺序的那条观测 |
| 漏步（顺序型跳号） | 跳号被检出的那条观测 |
| 漏步（闭合时集合比对） | 实例闭合时刻 |
| 超时 | 时限越过的时刻 |

**判定核心声明锚点与必需跨度，前后余量是运行参数（数据）在 supervisor 侧叠加。** 核心不读配置（§5.18），故它只说"这段区间是这个结论必需的"；把余量加宽到人能看懂上下文，是 supervisor 用运行参数做的事。这样改余量不动核心，也不改判定逻辑的形状。

**必需跨度不可被余量配置压缩。** 若某结论的必需区间比配置的窗口长（例如超时违规的必需区间覆盖整个等待过程），取两者的并集，不截断。配置能加宽，不能削掉证据本身。

关键帧默认在锚点取一张。

### 再切片：受滚动录像窗口约束的三个时段

再切片是**用新窗口从滚动录像重取**，因此能力边界就是滚动录像还在不在：

| 时段 | 能做什么 | 产物性质 |
|---|---|---|
| 锚点后 ≤ 原始素材窗口（默认 24 h） | 按任意新窗口重取 | 从未重编码的原始分段 `-c copy`，与首次切片同质 |
| 原始素材窗口 ~ 滚动窗口（默认 24 h ~ 7 天） | 按任意新窗口重取 | 从已归档压缩的分段取，画质为压缩后水平，**记录须标注素材代次** |
| 超过滚动窗口（默认 7 天） | **不能重取** | 只能复核当初已提取并仍保留在推理机的证据片段 |

**这条边界必须在界面上可见，不能让复核人点了才发现。** 每条证据显示"可再切片截止时刻"，过期后按钮置灰并说明原因。这是 §5.5 容量公式的直接后果，不是实现缺陷：滚动录像是有限窗口，延长它要么加盘要么开压缩（§5.19）。

**想让某些工位的再切片窗口更长，就延长该机的滚动录像窗口**——这正是 §5.19 里"压缩省下的容量换成可配置保留期"的用途所在。

### 再切片的执行路径

中心不推、推理机拉（§5.3），故再切片是**委托命令**，不是同步调用：

1. 复核人在中心发起再切片，给出新的前后余量（锚点不可改——锚点是判定事实，改锚点等于换一个结论的证据）。
2. 请求进入待办命令队列，`evidence` 拥有请求与结果记录。
3. 目标推理机下次拉取时取到该命令，从本地滚动录像切片并原子保存到本机证据目录，按幂等键回报证据 ID、摘要、窗口、素材代次和本机访问引用。
4. 中心把新引用**追加**为该判定的另一条证据，标注窗口参数、素材代次与发起人；本机新片段与中心引用都**不覆盖原片段**。

**延迟是一个拉取周期，不是实时的。** 界面按异步任务呈现进度（§5.15 已定长任务用 `GET /api/v1/jobs/{id}` 轮询），不假装同步返回。

**为什么不覆盖原片段**：原片段是当初判定的依据，覆盖它就是改写证据链。多条并存、各自标注来源，复核结论指向具体哪一条。

**推理机离线时**：命令留在队列，恢复后执行；若届时素材已过滚动窗口，命令以"素材已过期"失败结案并明确告知，不静默丢弃。

### 当前实现状态（S037–S039）

中心 `evidence` 已拥有再切片请求与状态（`evidence_reclip_request`，迁移 0058），并把委托命令入 `device` 原待办队列（`reclip_evidence` 命令类型，迁移 0059）；`device` 的 `claim_next` 按命令类型收窄，默认 `/device-commands/next` 只领取连接测试，再切片命令只由专用签名端点领取。

**S038 交付可复用的执行与成功追加接缝；S039 接入真实派发并结案失败。** 目标推理机复用首次切片能力（`evidence_media.slice_evidence`），按稳定请求 ID 把意图与产物持久化到本机 `local_reclip_request`（Edge schema _V18，_V19 追加冻结终局原因）：一旦定稿，该产物即权威，重启/重复领取/登记确认丢失都直接复用，不再查询或重切已过期或被压缩的滚动素材。若本机来源事实（冻结墙钟映射或来源相机路径）缺失，仍持久化可查询失败原因且不伪造映射；若原子定稿后写 SQL 前进程丢失，重试按稳定身份复用唯一已定稿产物而不重切。产物身份 = 原证据队列身份 + 稳定请求 ID + 实际覆盖窗口，追加新目录而不覆盖原片段；命令窗口必须覆盖本机冻结的核心必需跨度与锚点，否则拒绝且不切片。生产 `build_autonomous_runtime_from_file` 装配再切片领取循环，专用签名端点由生产 `create_app` 挂载。

中心回报走**专用主机签名端点**：先认证并结案 `device` 命令，再在同一请求事务内结案请求（成功记 `result_evidence_id`，迁移 0060；失败记可查询的机器原因）。非 `automatic` 来源的证据登记必须对应一条真实再切片请求（来源主机/工位/实例/锚点/窗口精确匹配），否则 409，伪造代次不能被追加；成功回报还要求结果引用与原证据的工位/实例/主机/锚点一致、与该请求的精确并集窗口一致且类型/状态适用，否则 409 并回滚命令结案，不把另一请求的结果算到本请求上。终局失败（素材已过期、素材缺失、切片错误、已定稿媒体损坏）由来源机回报具体机器原因并冻结；已成功或已失败的终局不被后到回报改写。

**失败结案与恢复等待分开。** 排队等待期间素材缺失、切片失败、已定稿媒体被篡改/删除都结案为终局失败并回报原因；中心暂时不可达属于恢复等待，保留本机待办下一轮重试，不结案成终局失败也不静默丢弃。首次终局原因冻结在本机（_V19），重启或重复领取复用同一原因，素材后来恢复或不同异常都不重切、不改因。再切片产物必须覆盖全部冻结来源与请求窗口，部分覆盖是终局失败，不冒充成功；首次切片的允许部分覆盖语义不变。命令窗口未覆盖本机冻结核心必需跨度时拒绝；已过中心截止且尚未产出任何产物时结案为归档过期（`archive_expired`），但已定稿产物优先于过期判定被复用，避免中心截止误杀已拥有产物的来源机。

**分段素材代次 sidecar 生产者契约。** 录像生产者在每个分段旁写入代次声明，实现按分段名替换 `.mp4` 后缀（如 `2026-10-09_12-00-00-000000.mp4` → `2026-10-09_12-00-00-000000.material.json`），内容为 `{"generation": "original"|"compressed"}`；未标注分段按未重编码的原始素材处理（当前 MediaMTX 生产者契约），标注非法或未知即拒绝切片，绝不静默回退成 `original`。切片读取**实际选中分段**的代次而非命令/登记时的代次，混合来源取确定性标签 `mixed`，并在每媒体元数据记录 `segment_generations` 计数。归档压缩生产者负责写 `compressed`（S048）；本票只读取与保留，不实现压缩执行器。

- **只登记元数据。** 中心只保存请求身份、来源主机、锚点、新余量、并集窗口、发起人与命令 ID；锚点与来源主机由原证据事实派生，客户端不能覆写，原证据不被修改（无 update/delete）。
- **可再切片截止是理论边界。** 界面截止 = 来源机在登记时冻结的 `required_from` + 冻结 `wall_offset` + 中心保存的该主机 `recording_window_seconds`；它只表达配置的滚动窗口，不代表来源机已实际应用该窗口或素材仍在。命令携带的 `available_until` 复用创建请求时的同一验收公式（`window_start` + 冻结 `wall_offset` + 来源机 `recording_window_seconds`），可能略早于界面按核心必需跨度起算的理论截止；来源机不得用本机当前配置或当前时钟自行猜归档截止。缺冻结时间元数据的旧登记保持“截止未知、不可再切片”，绝不用 `received_at` 或当前时钟反推。
- **权限与幂等。** 服务端要求 `evidence.evidence.view` + `evidence.review.edit`；同 `request_id` 同内容重放返回原记录，内容冲突 409 不覆盖；GET 按查看权限返回等待/失败状态。
- **Web 复核界面。** `EvidencePlayer` 按 Asia/Shanghai 显示每条/所选证据的绝对截止，过期置灰并说明原因、缺元数据显式未知并说明后端配置不适用；有编辑权限可提交新前后余量，一次提交意图只产生一个 `request_id`，失败按同一意图重放复用，不自动重试；等待/失败状态来自真实查询，并提供手动刷新读取后续终态，不自动轮询、不假装同步切片成功。已知失败原因码映射为人类可读解释，未知原因码显示原始码。只查看权限只读、无提交控件。
- **登记契约演进（Center-first）。** 证据登记新增可选冻结时间元数据（`wall_offset`/`required_from`/`required_to`）与核心必需跨度，旧登记缺失仍合法。登记体是严格模型，旧 Center 会拒绝携带新字段的整条登记，故必须 Center-first 部署：旧 Center 在时 Edge 保留本机待办与媒体，不隐式忽略字段、不自动降级。委托命令沿用既有严格 `command_type` + 固定字段解析，不新增 generation；S039 新增必填 `available_until`，由于 S038 的专用端点从未在生产挂载、也没有 Edge 运行循环消费该命令，该字段按 Center-first 匹配发布：先部署能下发 `available_until` 的 Center，再启用领取该命令的 Edge。成功回报体保持 `{evidence_id}` 不变，失败回报体为附加的 `{evidence_id: null, failure_code, detail}`。

### 与既有决策的关系

- 不新增模块：中心 `evidence` 已拥有“证据引用与人工复核”（§六），再切片请求与结果是它的记录；证据媒体文件由目标推理机的边缘运行时拥有。委托命令队列归 `device`（它已拥有推理机与委托执行这个 seam，ADR-0008 的“测试连接委托推理机执行”是同一机制）。
- 不改保留策略的类别语义（§5.19）：再切片产物属于原判定所在的保留类别。
- 不进实时路径：再切片是复核期行为，与 500 ms 预算无关；但它与压缩任务争同一套编解码资源，须同受限速与让路约束（§5.19 约束 3）。
