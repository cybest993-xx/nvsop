# 运行与证据媒体留在推理机，中心训练素材使用本地文件

## 状态

已采纳。该决定纠正此前“视频不跨中心”与“证据上传中心 MinIO”并存的冲突，并替代训练源视频必须使用 MinIO/S3 的首版假设。中心训练素材使用 `dataset` 拥有的本地持久卷；presigned/bucket/versioning 等 S3 特有契约与运行依赖按 Issue #350 移除。

## 背景

推理机是自治运行单元：取流、判定、处置、滚动录像和证据切片都在本机发生。中心是管理与聚合面，不在实时路径上。此前设计一方面要求“视频不跨中心”，另一方面又让违规证据上传中心 MinIO，并为偶发训练素材长期运行一套 S3 服务；这使媒体所有权、恢复语义、CI 基础设施和部署成本彼此矛盾。

训练素材的实际使用是低频、偶发上传，不要求分布式对象存储。它与现场持续产生的运行媒体也不是同一数据面。

## 决策

- **运行态录像、违规证据片段和关键帧由产生它们的推理机持有。** 首次切片和再切片都写入该推理机本地证据目录；中心不复制这些媒体字节。
- **中心 `evidence` 只拥有证据索引、引用、再切片请求和人工复核。** 推理机向中心上报证据 ID、来源主机、锚点、窗口、素材代次、sha256、大小和受控访问引用。中心确认表示元数据/引用已登记，不表示存在中心媒体副本。
- **证据媒体删除由推理机执行。** 中心拥有全局/工位保留策略与引用保护事实，推理机按同步后的当前策略和保护状态删除本机媒体；未知或失配保护状态不能当作无人引用。
- **训练源视频是中心管理资产，但不进入 PostgreSQL BLOB。** Web/脚本经正式授权 API 逐个流式上传，`dataset` 把临时文件校验后原子定稿到中心本地持久卷，PostgreSQL 只保存业务状态和文件元数据。
- **首版不要求 MinIO/S3，也不维护双生产路径。** #350 删除 presigned/bucket/versioning 等 S3 特有契约和运行依赖；未来只有出现真实的多节点/远程对象存储需求时才重新评估 adapter。
- ADR-0011 的标注派生媒体授权网关继续有效；它是派生媒体读取的有限例外，不改变上述所有权。

## 不采用的方案

- **把运行/证据媒体集中到 MinIO**：复制本来属于推理机的数据，使中心存储与网络成为额外故障面，并让中心承担与管理面无关的大字节生命周期。
- **把训练/证据视频存进 PostgreSQL BLOB 或 Large Object**：把 GB/TB 级媒体耦合进数据库 WAL、备份、恢复和复制，扩大数据库故障与运维半径。
- **仅为偶发训练保留 MinIO**：S3 签名、bucket/versioning、secret、容器镜像和真实 CI fixture 的持续成本超过当前需求。
- **同时保留本地文件和 S3 fallback/双写**：没有当前业务合同支撑两条生产路径，只会扩大状态空间和恢复语义。

## 后果

- 中心备份与推理机备份必须分开裁决：中心 PG 和训练素材卷是一组；推理机 SQLite/证据媒体是否备份由 Q36 决定，中心元数据不能被解释为可重建媒体。
- 证据相关开放 Issue 必须从“上传/中心对象确认”改为“本地媒体持有 + 中心引用登记/授权 + 边缘保留删除”。
- 训练/浏览器验证必须从 MinIO 真实依赖迁移到 dataset 本地文件真实路径；MinIO 相关历史 Issue/PR 仍保留为旧实现追溯。
- 纯 Edge 变更不应因为无关的中心训练存储基础设施失败而被阻塞；CI scope 在 #350 中按真实依赖重新核对。
