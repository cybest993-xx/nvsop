# 设备凭据存在推理机本地，中心不代管

相机与连接器的凭据在推理机本地录入、本地加密存储、本地校验。中心只存"该设备凭据已配置 / 未配置"的状态标志，不存密文，也不代管。

## 理由

中心一旦代管凭据，推理机重启就依赖中心可达——与"推理机是自治判定单元"直接冲突（[ADR-0005](0005-judgment-runs-inside-the-inference-host.md)）。中心离线时无法起流，等于把管理面故障放大成产线停摆。

中心因此自然满足"不提供凭据明文读取接口"：它从来没有过密文。

## Considered Options

- **中心加密存储 + 生成含凭据的部署包供下载**（原方案）：`.env` 与 mediamtx 配置必须含 RTSP 账号密码，下载即明文导出，与"不提供明文读取接口"的不变量直接矛盾——只是换了个标签。
- **中心加密存储 + 推理机运行时鉴权拉取**：不变量保住了，但把中心变成推理机启动的运行时依赖，仍违反自治约束。
- **推理机本地持有（采纳）**：中心不持有秘密，推理机不依赖中心。

## Consequences

- 中心生成的推理机配置骨架不含秘密，只有占位符与说明。
- 推理机本地密钥由部署时挂载的只读 secret 文件提供，不进入 Git、日志、API 响应或导出物。
- 凭据写入后只能覆盖或用于本机真实连接测试，不提供明文读取接口。诊断日志只记录操作人、目标、时间和结果。
- 代价是凭据轮换要逐机执行。50 台机以上时应提供批量脚本，但脚本从本地或运维通道运行，不经中心代管。
- 中心界面上"测试连接"对相机凭据类操作转为**委托推理机执行并回报结果**，中心不直接持有凭据发起连接。
