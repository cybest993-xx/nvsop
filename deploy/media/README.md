# Issue #34 media smoke environment

This is a no-GPU, synthetic-source deployment for validating the direct MediaMTX path without
an NVIDIA backend or a real camera. It exposes one passthrough path and one real CPU-transcoded
path. It pins MediaMTX `v1.21.0` and the FFmpeg `6.1-ubuntu` image by digest. The CI host also
pins `ffmpeg`/`ffprobe` to `6.1.1` for the system probes.

```sh
docker compose -f deploy/media/compose.yaml up -d
curl -fsS 'http://127.0.0.1:9996/list?path=synthetic&start=2026-09-12T00:00:00Z&end=2026-09-13T00:00:00Z'
curl -fsS 'http://127.0.0.1:9996/list?path=cpu-transcoded&start=2026-09-12T00:00:00Z&end=2026-09-13T00:00:00Z'
# WHEP 预览使用 POST /<path>/whep 并交换 application/sdp，而不是经中心 API。
docker compose -f deploy/media/compose.yaml down -v
```

The browser-facing WebRTC signaling address is `http://127.0.0.1:8889`, with ICE UDP on
`8189/udp`; the native recording API is the independent address at `http://127.0.0.1:9996`. The
example allows only the loopback origins used by the local synthetic environment.
Production configuration must set its explicit HTTPS origin and keep the MediaMTX ports reachable
only from the operator network.

The edge configuration generated by the center uses the stable `camera-<uuid hex>` path and
reads the two camera credentials from the exported local `credential_files` paths. It never
puts those values into the center export, browser requests, or diagnostics.

To apply a center export, prepare the edge JSON once with the local binary, bind, recording
segment, preview-release, transcode-thread, startup, and explicit browser-origin settings under `media`, then merge each new export:

```sh
python3 scripts/apply_media_export.py center-export.json edge.json edge.next.json
# 缩短已应用录像窗口时，先用真实分段估算并记录操作员确认：
python3 scripts/apply_media_export.py --confirm-retention --operator "$USER" center-export.json edge.json edge.next.json
mv edge.next.json edge.json
NVSOP_EDGE_COMMAND_CONFIG_FILE=edge.json python3 -m edge_runtime
```

The merge script copies only the center's host/camera topology and keeps those local settings;
newly exported cameras default to `sop_execution: true`, while an existing local `false` is kept
for a deliberately non-SOP debug camera. Its atomic output is mode `0600`. Mount the paths in each
exported `credential_files` object as read-only files on the target inference host.
