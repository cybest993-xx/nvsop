# 跨模块用例共享一个请求级事务

一个 HTTP 用例常跨模块：发布模板要写 `template` 的版本行，并在同一事务内追加 `job` 的 outbox 行（若发布触发制品生成）。我们由 HTTP 适配层开启并提交**单个请求级 Unit of Work**，模块门面方法只参与事务、不自行提交，`Session` 经请求作用域依赖注入传入。

## Consequences

- 事务性 outbox 因此成立：业务变更与任务入队原子写入，提交后再投递 Redis（[ADR-0004](0004-postgres-is-the-job-authority.md)）。每模块自开事务会产生"业务已改、任务未登记"的中间态，而这些任务的状态是要在 Web 上追溯的业务事实。
- 概览页的跨模块聚合也依赖它：各模块用例层各出一个 `summary()`，适配层在同一 UoW 内调用并组装，读到的是一致快照。
- 代价是模块共享同一事务，模块边界不再由事务边界兜底。防越界因此完全依赖两道机械检查：`import-linter` 契约（跨模块只能导入他人 `api` 模块）与迁移所有权检查（一个迁移文件只能触及其前缀模块拥有的表）。这两道检查是本决定的前提，不是可选增强。

## 注

本 ADR 早期版本以"发布模板要同时追加 `auth` 的审计事实"立论。审计表已在方案中明确取消（变更归属由各实体的 `created_by`/`updated_by`/发布者列承担，操作痕迹由诊断日志承担），故论据换为 outbox 与聚合读一致性。决定本身未变。
