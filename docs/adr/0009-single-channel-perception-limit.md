# 单通道感知下漏做起始动作的作业不被记录，这是设计取舍

仅以动作编号作为开始信号时，操作员若漏做**起始动作**，SOP 实例开不了，该遍作业完全不被记录——不是被误判为违规，是不存在这条记录。本 ADR 明确这是设计取舍而非实现缺陷，并记录可选的补偿手段。

## 为什么不能用"检测到任意动作就开实例"

那会把返工、擦拭、取料等非 SOP 动作误判为作业开始，产生大量假实例，每个都以漏步收尾。误报的代价高于漏记录：现场对误报的容忍度极低，一旦告警不可信，整个系统会被绕过。

## 为什么不能靠推断补上

推断起始只有两类线索：动作序列形状与时间间隔。前者正是基座启发式失败的地方（[ADR-0006](0006-cycle-boundary-is-declared-not-inferred.md) 的返工实测）；后者在节拍不固定的工位不成立。用不可靠的推断换取"不漏记录"，会把已知的、可解释的局限换成未知的、不可解释的误判。

## 补偿手段（部署期配置，非架构前提）

为该工位配置一个外部信号点位作为开始信号，语义如"工件到位"。物理事实不依赖动作识别，因此漏做起始动作时实例照样开启，随后判为漏步。

这是**部署期的配置选择**：没配连接器的工位走同一套判定代码路径，只是可声明的信号源少一个。代码中不得出现 `if 配了连接器: ... else: ...`。

## Consequences

- 交付与销售必须显式说明该局限，不能让客户在现场自己发现。仅动作编号触发的工位，其"作业遍数"统计是下界而非精确值。
- 对漏记录敏感的工位（例如按产量对账的工位），部署时应配置物理开始信号，或用外部计数信号做遍数对账。
- 界面需要能区分"该工位无外部开始信号"与"该工位有但未触发"，否则运维无法判断一段空白是没人干活还是漏记录。
