# SOP 合规检测系统 — 方案与开发路线

日期：2026-08-30
基座：[`NVIDIA/sop-monitoring-blueprints`](https://github.com/NVIDIA/sop-monitoring-blueprints) —— **仓库固定，版本不固定**（跟随 NVIDIA 仓库更新）。本文各项实测结论均标注复核时所在提交；NVIDIA 仓库更新后须重跑契约测试（§5.9）确认前提未变。

本文事实的复核基准：`6e149568`（初次实测）与 `69352021`（当前 main，复核）。两者 `sop-inference-bp` **零差异**，故推理服务相关结论在两个提交上等价成立。

本文三类结论分别标注：**【已定】**= 需求方已确认；**【实测】**= 本机跑过、有数据；**【待确认】**= 我的建议，需你裁决。

## 一、产品定位与硬约束

把工厂标准作业转成机器可执行的模板，在现场实时回答：当前在做什么、是否合规、偏离后留什么证据、触发什么响应。

**【已定】基座是本产品的躯干，不是外部依赖。** NVIDIA 仓库已实现的能力原样复用；接近但不够的就地改造；基座完全没有的才新建。不允许出现"基座有一套、我们再写一套"的重复实现——这条约束优先于"`vendor/` 只读"这类洁癖，见 §5.11 与 [ADR-0007](../adr/0007-base-is-the-trunk-not-a-dependency.md)。

**【已定】交付的必须是真实可用的系统，不允许任何 mock / 模拟实现。首要价值是实时防错。**

**【已定】推理机是自治判定单元；中心不可达时现场继续工作。** 每台推理机独立完成取流、感知、判定、违规锁存、处置（含写输出点位）与证据缓冲，本地持有模板版本、设备配置与凭据。中心是管理面与聚合面，不在实时判定路径上。中心离线时推理机按最后确认的模板版本继续判定与处置，本地排队，恢复后对账；处置不重复执行，证据不丢失。见 [ADR-0005](../adr/0005-judgment-runs-inside-the-inference-host.md)。

**【已定】性能优先。每个成功实时结果的端到端延迟目标为 ≤ 500 ms。** 该目标按结果类型分两个起点（§5.6）：**到达即判类**（错步、反序、超时、顺序型模板的跳号漏步）起点是形成该结果所需的最后一帧在相机侧产生；**闭合类**（实例闭合时的集合比对）起点是闭合条件成立时刻。终点同为对应状态或判定完成 Web 渲染。目标环境门禁要求测试窗口内超预算结果为零，同时报告 p50/p95/p99、最大值、超预算计数、队列深度与积压趋势；未在目标 GPU、相机、网络和浏览器上通过前，不把该目标表述为已实现能力。

**【已定】优先对齐推理服务公开契约，不为传输层另造体系。** 视频帧留在推理机；DeepStream/PyServiceMaker 形成 chunk，经 VLM 分类后由本机 supervisor 消费 SSE 判定，再由本机上报中心。REST/JSON 负责配置、查询和命令；中心向 Web 推送 SSE。关键路径不增加 Kafka、gRPC、自定义 WebSocket 或数据库轮询，除非 profiling 证明必要。

## 三、已确认决策清单

| Q1 | 判定挂载点 | **SOP 实例**（工位上一次有明确起止的作业周期）；基座 cycle 启发式被声明式边界取代（§5.1） |
| Q2 | 感知路径 | 官方 **DDM + vLLM**，**不改感知计算路径**；改造只涉及边界、有效性与处置（§5.11） |

| Q4 | 发布治理 | **模板草稿（可编辑）→ 模板版本（不可变）两态**；不设待审核与已退役状态；版本 + 工位绑定 + 原子切换 + 回滚（重新绑定历史版本）；**不做签名**；保留 sha256 完整性校验 |
| Q5/Q14 | 权限 | 本地账户 + 自定义权限；角色是权限集合、用户可有多个角色；首版角色见 §5.4 |

| Q15 | 实例边界 | 见 §5.1（声明式边界替换基座启发式） |
| Q16/Q19 | 连接器 | 输入 + 输出双向；**连接器是可配置项，非所有工位都需要**；判定逻辑不因有无连接器而改变代码路径；连接器运行时在推理机内（§5.8） |
| Q17 | 多机拓扑 | 每路相机绑定到指定推理机；一台推理机可运行多个推理后端进程，**每个后端承载一份模板**（§5.10）；改绑须经交权握手，强制改绑需二人确认（§5.17） |

| Q24 | 相机 | **海康威视网络摄像机**，RTSP 主码流 `101` / 子码流 `102` |
| Q26 | 微调策略 | **先训练 DDM，VLM 使用公开权重**；首切片只导入、校验训练数据并生成 DDM 标注，不编排训练 |

## 四、待确认项

**Q25 AI 建模板做到哪一步**：(a) 只生成提示词与 `actions.json`；(b) 再加步骤对齐（调推理服务，给出每步在模板视频中的时间码供人工核对）；(c) 再加微调数据生成。
➡️ 建议 **(b)**，(c) 另行裁决后再排期。纯 (a) 太薄——客户无法在上线前判断模板可用。此处只是建议，不因软件 MVP 分期而自动确认，直接相关的步骤对齐切片在裁决后排期。

**Q36 备份与恢复**：全仓库尚无备份/恢复要求。待定：中心 PG（含训练侧 schema）与 MinIO 的备份对象与周期；推理机本地 SQLite 是否纳入备份，及其内容可从中心重建到什么程度；恢复演练是否进发布门禁（当前 [`deployment/upgrade.md`](../deployment/upgrade.md) 只定义迁移/兼容升级证据，不替代恢复策略）；恢复后与推理机的对账语义，避免重放已执行的处置。
➡️ 建议：中心 PG + MinIO 为备份权威；推理机 SQLite **不入备**——在飞实例按 §5.7 语义在重启后记为"运行中断"结案，已上报数据以中心为准，未上报的本地队列丢失即接受，不为它建第二套备份链路。恢复演练进发布门禁。**它是运维交付项，不阻塞编码。**

**硬件门禁不是开工前提**（见 §5.21）：GPU 档位、单节点路数、VLM 实时性、海康型号与编码、ISAPI 投递方式、时间同步精度的实测值属**部署期验证**，[`target-environment-validation-matrix.md`](../research/target-environment-validation-matrix.md) 是其验收清单与证据格式。未实测时不得标称对应门禁通过，但软件按泛化设计正常开发。

**默认按工程惯例处理，如需调整请指出**：全机 NTP 同源，推理机上报时钟偏移，超阈值该路进不可判定；进程/容器重启则在飞实例记为"运行中断"结案，不跨重启恢复（本地状态可查，但不续接为同一连续观测）；**所有保留时长与片段窗口均为可配置项，默认值见 §5.19 总则的表**——录像 7 天、观测/判定 90 天后聚合归档、证据不随录像过期删除都是那张表里的默认值，不是写死的常量。

## 六、系统结构

**【已定】技术与部署基线**：中心后台采用 FastAPI + SQLAlchemy 2.x + Alembic；基础 Web 采用 Vue 3 + TypeScript + Vite，并通过 OpenAPI 生成客户端。Nginx 是统一访问入口。Nginx、FastAPI、ARQ worker、PostgreSQL、MinIO、Redis 与原样复用的训练微服务由一份中心机 Compose 统一安装和运维。正式部署必须使用 HTTPS，并使用 `HttpOnly + Secure + SameSite` 会话 Cookie；固定 main 本地开发实例默认使用 HTTP，`allow_http` 仅限该部署模式，也可显式设置 `NVSOP_DEV_PROTOCOL=https` 验证本地 TLS 路径。修改请求仍执行 CSRF 校验，不在 `localStorage` 保存长期令牌。

中心后台是**模块化单体**：业务模块在一个 FastAPI 部署单元内通过进程内接口协作，各自拥有行为、表和迁移；首版不引入内部 HTTP、服务网格、消息总线或分布式事务。

首切片持久化只启用 PostgreSQL、MinIO 与 Redis；TimescaleDB 在 `monitor` 开始持久化时序上报时的实施切片中再启用。推理机本地状态用 SQLite（§5.7）。

**训练侧 `metadata_db` 与中心后台合并为一个 Postgres 实例、两个 schema**（Q35）：中心业务一个 schema，原样复用的训练微服务一个 schema。训练是低频活动，不值得为它单立一个实例与一套独立的备份、监控与升级流程；原样复用的训练服务只改连接串，不改代码。两个 schema 由不同的数据库角色持有，中心迁移不触碰训练 schema，训练服务也不读中心表——它们之间没有跨 schema 外键。

**【已定】统一访问入口是控制面入口，不是全流量中继。** Nginx 只承载 Web 静态资源、中心后台 REST/JSON、会话、小数据实时更新，以及原样复用的标注 UI 与训练微服务（在网关补鉴权）。视频的 WebRTC 信令与媒体均由浏览器直连推理机 mediamtx。

```
中心机（管理面，非运行面）                推理机 A（自治判定单元）      推理机 B
├── Nginx 统一访问入口                   ├── 推理服务容器             ├── 推理服务容器
│    ├── Vue3 前端                       │    DeepStream→DDM→vLLM     │
│    ├── /api/v1 → FastAPI               │    →SSE→supervisor 判定     │
│    └── 反代：标注 UI / 训练微服务       ├── supervisor（锁存/处置/    ├── supervisor
├── FastAPI 后台（单一入口点）            │    上报/对账/证据切片）      │
├── PostgreSQL（+Timescale 后置）         ├── 连接器运行时              ├── 连接器运行时
├── Redis / MinIO / ARQ worker           ├── mediamtx                 ├── mediamtx
└── 训练微服务（原样复用）+ metadata_db   └── SQLite 本地状态          └── SQLite
                                               ↑                          ↑
          ← 上报（幂等 upsert）                相机 1~8                  相机 9~16
          → 拉取（模板/配置，推理机主动）  （视频不跨中心；中心离线现场继续判定与处置）
```

| 模块 | 拥有 |
|---|---|
| `auth` | 用户、角色、权限、会话 |
| `device` | 推理主机、工位、相机、推理后端、连接器配置、凭据配置状态标志、健康聚合、工位运行参数覆盖、委托命令队列 |
| `execution` | 工位物理执行权：归属、改绑握手、强制改绑的双人确认、物理执行租约与续期（§5.17） |

| `monitor` | 推理机上报的完整镜像：SOP 实例、判定、锁存违规、处置记录、流健康；看板状态（[ADR-0010](../adr/0010-alert-merges-into-monitor.md)） |
| `evidence` | 证据引用、片段窗口与再切片请求、人工复核（§5.20） |
| `retention` | 数据保留策略、判定类别解析、变更影响估算与引用保护（§5.19） |
| `job` | 异步任务权威与投递（outbox；ADR-0004） |

**`retention` 拥有策略、不拥有数据**：它解析"某实例属于哪个保留类别、该类别留多久、何时压缩"，删除由数据拥有者在自己的表上执行（`evidence` 删证据、`monitor` 删记录与处置归档、边缘运行时裁 SQLite 与录像）。它独立成模块的理由是有一条跨模块不变量需要单一所有者：**保留策略不得删除仍被开放违规、在审复核或未结案实例引用的数据**——该约束横跨 `monitor` 与 `evidence`，散在各模块无人能强制。反过来让它也持有数据就会变成一个跨界读写他人表的模块，违反所有权规则。

**`execution` 与 `device` 分开的理由**：`device` 的变更驱动是"现场装了什么设备"，是可逆的配置 CRUD；`execution` 的变更驱动是"哪台机有权驱动这个工位的执行器"，是带 TTL 的跨机安全状态机，且承载全系统唯一的双人确认操作（§5.17）。把它混进 `device`，一次相机改名和一次可能同时驱动两套物理执行器的改绑会共用同一个模块接口与权限面。它有自己的不变量——**任一工位在任一时刻最多一台推理机持有未过期的物理执行权**——这条要在模块内可强制，不能靠调用方自觉。

**上报接收面是两个模块，不是一个也不是三个**：`monitor`（推理机上报的完整镜像，含违规与处置记录）与 `evidence`（证据引用与复核）由同一个上报入口写入，但变更驱动与行为主体不同：`monitor` 只随上报契约变，由机器写入；`evidence` 还有**人工复核**这个完全不同的行为主体与生命周期（证据不随录像过期删除，复核由人触发且不改写原判定）。合成一个模块会让"机器写入的镜像"与"人参与的复核流程"共用一个接口。违规与处置归档曾拟独立为 `alert` 模块，理由是"随处置动作种类变"；处置类型归推理机拥有后该理由不再成立，已并入 `monitor`（[ADR-0010](../adr/0010-alert-merges-into-monitor.md)）。上报入口适配层在同一请求级 UoW 内写两个模块——这是 ADR-0002 已经允许的组合，且该适配层只做分发，不含判定逻辑。

诊断日志与 correlation id 传播不是模块，是共享基础设施（§5.15）。

**中心不再有的东西**：`judgment` 模块（判定移入推理机的判定核心）、`runtime` 的 ingest 进程（不再订阅 SSE）、流租约表（ADR-0001 作废，§5.7；但工位物理执行权仍需管，见 §5.17）。中心的 `monitor` 是**上报镜像**，不是判定权威——它的行覆盖来自推理机的幂等 upsert。

`dataset` 是独立模块而非 `template` 的一部分：`CONTEXT.md` 对「训练数据集」的定义明确写了它不定义 SOP 模板，并把「SOP 模板」列为 _Avoid_ 项，合并二者会在代码层重新粘合术语层刻意拆开的概念。

**推理机侧组成**（`apps/edge-runtime/`，包清单与所有权表见 [`repository-architecture.md`](repository-architecture.md)）：判定核心（纯标准库、纯函数、无钟无 I/O，§5.18）、边界求解、本地状态（SQLite）、supervisor（SSE 消费与判定调用 / 请求看护 / 锁存 / 处置派发 / 上报对账 / 计时器持有 / **一反应一事务的持久化**）、连接器运行时（每个已配置连接器一个）、mediamtx 看护、证据切片、录像压缩归档任务（§5.19）。`vendor/` 内只留一处最小 hook 调用本包（§5.11）。

**边缘包间依赖方向**（由 import-linter 契约兜底，见 [`repository-architecture.md`](repository-architecture.md)）：`supervisor → local_state → judgment`；`connectors → judgment` 与 `supervisor` 的输入词汇；`stream_health` 不导入本包任何东西；运行循环是唯一的装配根，也是唯一同时认识全部包的地方。存储模块只认识领域类型，不认识编排它的人——反过来的方向（存储导入 supervisor）已实测会让"一反应一事务"退化成调用方契约。

**依赖规则**：判定核心不依赖任何相机 SDK、推理框架或连接器实现，只消费归一化观测；中心各模块各自拥有数据表，不跨模块直接读写；前端只调后端用例，不承载判定规则。

**【已定】边界靠机械检查，不靠评审。** 每个中心模块一个 Python 包，包内 `api.py` 是唯一允许的跨模块导入目标；`import-linter` 契约在合并门禁中强制：判定核心不得导入任何适配器包、任意模块只能导入他人 `api`、`adapters/*` 不得被 domain 层导入、**`vendor/` 内的 hook 只能导入 `edge-runtime` 中指定的那一个健康事件入口模块**（§5.11）。最后一条使"补丁面只剩一处纯追加"从纪律变成可检查的事实——没有它，那处 hook 可以在后续修改中逐步长出对 `edge-runtime` 任意内部模块的依赖，而 `vendor/` 里的代码不受本仓库 lint 覆盖这一点会让它长期看不见。物理表名带模块前缀（§七），使迁移所有权可纯静态判断。

**【已定】跨模块用例共享一个请求级事务**（[ADR-0002](../adr/0002-request-scoped-unit-of-work.md)）：HTTP 适配层开启并提交单个 Unit of Work，模块门面只参与、不自行提交，`Session` 经请求作用域注入。代价是事务边界不再兜底模块边界，故上述机械检查是本决定的前提而非可选增强。

**【已定】迁移为单一线性 Alembic 历史**，单一 `versions/` 目录，文件名前缀标注所属模块（`0007_template_...`）；合并门禁检查一个迁移文件只触及其前缀模块拥有的表。

**【已定】工作区与工具链**：工作区成员、运行时版本与检查命令以根清单、版本文件、[`repository-architecture.md`](repository-architecture.md) 与 [`repository-verification.md`](repository-verification.md) 为准。**`apps/edge-runtime/` 的判定核心只依赖标准库**，运行在推理机 supervisor 进程中；该约束用于可测试性与可移植性（[ADR-0005](../adr/0005-judgment-runs-inside-the-inference-host.md)）。`vendor/` 内的最小 hook 才运行在基座容器中，其解释器由基座决定。

**【已定】配置与秘密**：`pydantic-settings` 单一 `Settings`，环境变量为唯一来源，秘密经 `*_FILE` 路径变量读文件而非读值；启动强制校验无默认弱值，缺失即拒启，不降级为不加密。推理机本地凭据同规则（§5.12）。

**【已定】会话与口令**：会话记录由 `auth` 存于 PostgreSQL（重启不掉线，可强制下线），口令用 Argon2id。不用无状态签名 Cookie——无法即时吊销。

**【已定】基础 Web 栈内选型**：Element Plus + Pinia；OpenAPI 生成的 TS 客户端置于 `apps/control-web/src/api/generated` 并提交，CI 校验重新生成后工作区干净。`packages/` 需两个真实调用方才允许上移。

**【已定】API 前缀**：控制面路径固定 `/api/v1`，但该前缀不是版本轴，不会出现 v2（[ADR-0003](../adr/0003-api-v1-is-a-fixed-prefix.md)）。`openapi.json` 由 FastAPI 生成并导出到 `packages/contracts/`；契约检查必须让删除路径/字段、新增必填字段、收窄类型失败。推理机是可能非同步升级的客户端，靠启动时版本握手而非 URL 版本。

**契约清单**：**推理服务 OpenAI 兼容 API**（基座既定，我们是同机消费者）、**上报契约**（推理机→中心：`ReportedDecision` / `ReportedViolation` / `ReportedHealth`）、**拉取契约**（中心→推理机：`TemplateBundle` / `DeviceConfigBundle`）。后两者字段留到运行切片按真实数据确定（§5.15）。

实时结果路径固定为：

```text
相机主码流 → DeepStream → chunk → DDM → vLLM → 判定核心（序列比对+边界+有效性+三值）
            → 本机 supervisor：违规锁存 / 处置执行（含写输出点位）/ 证据切片
            → 上报中心 → 中心 SSE → Web 看板
```

判定与处置在虚线以上全程不跨机。中心 SSE 只服务看板，不在防错功能路径上。REST 不轮询替代该流。

## 七、数据模型要点

物理表名带拥有模块前缀，使迁移所有权检查可纯静态判断，且 grep 一个前缀即得该模块全部持久化面。

### 中心（PostgreSQL）

- **配置域**（`device`）：`device_inference_host`（物理推理机：主机标识、网络地址、mediamtx 地址、健康状态、时钟偏移、**录像滚动窗口时长与磁盘水位阈值**，§5.19）、`device_inference_backend`（**一份模板配置的进程端点**：外键 → host、base_url、承载的模板绑定、健康状态）、`device_station`（含运行参数覆盖状态与覆盖组，§5.3；保留策略覆盖状态与覆盖组，§5.19）、`device_camera`（主/子码流路径、凭据已配置标志、外键 → station 与 inference_backend）。
- **物理执行权域**（`execution`）：`execution_station_grant`（某工位的物理执行权当前归哪台推理机、租约到期时刻、续期时刻）、`execution_handover`（改绑握手请求与交权确认；强制改绑的两名确认人、警示已展示标志、确认时刻）。见 §5.17。
- **委托命令队列**（`device`）：`device_pending_command`（目标推理机、命令类型 = 测试连接 / 再切片、参数、幂等键、状态与回报结果）。中心不推、推理机拉（§5.3），故一切需要推理机代为执行的动作都经此队列；ADR-0008 的"测试连接委托推理机执行"与 §5.20 的再切片是同一机制的两个命令类型。
- **保留策略域**（`retention`）：`retention_policy`（全局默认与工位覆盖组：三个判定类别各自的证据保留时长、记录明细保留时长、压缩起始年龄、聚合归档年龄；覆盖为整组替换）、`retention_sweep`（每次回收任务的执行记录：范围、删除计数、跳过计数与跳过原因、起止时刻），使"上次删了什么、为什么跳过"可查。录像滚动窗口不在此表——它按推理机配置，属 `device_inference_host`（§5.19）。
- **连接器域**（`device`，仅配置）：`device_connector`（类型 = `hikvision_isapi` / `board_card`、连接参数、健康状态、**该适配器的能力声明**：投递方式、最大投递延迟、是否保序、是否可能丢边沿、时间戳来源，§5.8）、`device_connector_point`（方向 in/out、点位号、语义标签如"工件到位"/"停线联锁"、外键 → connector 与 station）。模板按语义标签引用点位，不写死设备地址。**工位可以没有任何连接器。**
- **模板域**（`template`）：`template_sop`、`template_version`（不可变，含 Excel 导入引用、actions.json、vlm_prompts、**运行参数默认值**、顺序性声明、sha256、发布者与发布时刻）、`template_draft`（可编辑，含 `revision` 乐观锁列）、`template_station_binding`（`desired_version` / `reported_version`，后者由推理机上报，§5.3）。
- **训练数据域**（`dataset`）：`dataset_training_dataset`、`dataset_member`（**数据集内的视频**：MinIO key、来源、大小、sha256、时长、编码）、`dataset_action_list_revision`、`dataset_annotation_context`、`dataset_annotation_submission`、`dataset_annotation_execution`（动作时间段标注及其不可变执行候选）、`dataset_usage_check`（DDM/VLM 用途、状态、原因）、`dataset_artifact`（生成的 DDM `annotation.json` 等派生制品及摘要）。上传、标注、用途检查、转换和训练是不同状态，不合并成一个"成功"。
- **上报镜像域**（`monitor`）：`monitor_sop_instance`（起止、闭合原因、边界信号来源、上报时刻）、`monitor_decision`（hypertable，判定结果 + 原因码 + 模板版本 + 推理机自报模型标识）、`monitor_observation`（hypertable，动作编号与外部信号同表）、`monitor_stream_health`（hypertable，含时间锚定偏移）、`monitor_violation`（kind、锁存标志、来源推理机）、`monitor_disposal`（action、执行状态、幂等键）。全部按事件 id 幂等 upsert，权威在推理机本地；违规与处置的执行权威同样在推理机，这两张表是归档载体（[ADR-0010](../adr/0010-alert-merges-into-monitor.md)）。
- **证据与复核域**（`evidence`）：`evidence_evidence`（MinIO key、类型、**锚点时刻、窗口前后余量、素材代次、发起来源=自动/再切片**）、`evidence_reclip_request`（新窗口参数、目标推理机、状态、发起人、失败原因如"素材已过期"）、`evidence_review`（复核结论、复核人、指向具体哪条证据）。
- **基础域**（`auth`）：`auth_user`（含停用状态）、`auth_role`、`auth_permission`、`auth_role_permission`、`auth_session`。**不设 `auth_audit_log`**（§5.15）。
- **作业域**（`job`）：`job_application_job`（异步任务权威与 outbox；ADR-0004）。

**判定结果表归 `monitor` 而非独立的 judgment 模块**：判定核心是推理机内的纯函数，永久无表。中心侧只存上报镜像，命名与所有权都归 `monitor`，表前缀规则与纯函数要求因此不再互锁。

### 推理机（SQLite，每机一份）

`local_config`（已确认的设备配置与凭据密文）、`local_template_version`（已确认模板版本 + sha256）、`local_sop_instance`、`local_decision`、`local_violation`（锁存）、`local_disposal`（处置记录：幂等键、目标点位、操作人、执行结果；**它就是点位写入的去重账本**，连接器运行时与处置派发共用这一张表，不各建一份）、`local_report_queue`（待上报，至少一次）、`local_evidence_queue`（待上传）。

**关键不变量**：违规一经确认即锁存，不因后续补做或处置失败而消失；锁存发生在推理机本地，不依赖中心可达。

## 八、开发路线

本节只调整交付次序与验收分期，不降低产品能力、架构边界或安全不变量。旧路线把“阶段 0（4090 到位前）”与“阶段 1（4090 到位）”写成前后阻塞，造成 GPU 既像编码前提又像发布门禁的歧义；以下改为**软件实施进度**与**发布/现场验证进度**两条并行进度。

### 8.1 固定范围与双进度

本轮软件实施范围固定为 [#1](https://github.com/cybest993-xx/nvsop/issues/1) 追踪的 **#24–#35、#44–#60，共 29 个实施任务**。范围包含多机部署、`execution` 模块的物理执行权、正常交权与双人强制改绑，以及板卡连接器适配；不复活已撤销方案，不把尚未拆出的阶段 4（统计报表、整改闭环、商业化加固）塞入本轮。

| 进度 | 口径 | 退出条件 |
|---|---|---|
| 软件实施 | 真实业务逻辑与可运行闭环；测试可在已记录 seam 使用合成输入或适配器替身，但不能以模拟生产实现、占位接口或假成功结案 | 分期后归属软件任务的验收条件、必要验证、独立审查与合并均完成，且后置原始验收条件已有开放关联验证任务，才可关闭该任务 |
| 全量集成与发布/现场验证 | 全量跨模块 system/browser E2E、GPU、真实相机/连接器、目标网络、多机现场、组合故障、长稳、规模性能与压缩争用等证据 | 由单独关联的开放验证任务承载，保留原验收要求和从实施任务到验证任务的精确追溯；验证未完成不倒推软件任务完成 |

状态只根据 Git 合并证据、必要门禁和 issue 状态更新；本路线不把“已有代码”“单元测试通过”或文档描述当作完成。#1 同时记录两条进度，最终验收前不关闭。

### 8.2 软件实施顺序（不以 GPU 到位为前提）

下列是依赖导向的交付顺序，不是把所有票强行串成一条线；每票的 GitHub 依赖仍是实际阻塞依据：

1. **控制面与真实配置链路：#24–#35。** 依次落地推理机/后端、工位/相机、连接器与能力声明、模板草稿与不可变版本、绑定对账、训练数据集与标注入口、训练服务接入、MediaMTX 预览录像和真实配置概览。保留原票的授权、凭据、版本完整性、数据集状态和浏览器验收条件。
2. **边缘配置确认与判定入口：#44–#45。** #44 负责按推理机裁剪拉取并原子确认；#45 负责动作、健康事件、时间锚的 SSE 归一化和回放契约。架构审查记录的 **T1** 仍是 #45、#50、#51 之前的必要顺序约束；本路线不声称 T1 已执行，必须以代码和 issue 证据为准。
3. **运行闭环与自治副作用：#46–#54。** 先建立上报镜像和看板，再完成实例生命周期、违规锁存、非点位处置、输出点位处置、证据切片/复核与中心离线恢复。所涉关键风险的必要证据按 [`repository-verification.md`](repository-verification.md) 随实施完成，不推迟到现场阶段。
4. **保留与介质安全：#55–#57。** 先实现可配置保留策略、引用保护与磁盘水位安全，再实现可暂停、可让路、校验后替换的录像压缩。软件契约可在无 GPU 环境验证；CRF、NVENC 争用和目标容量仍属于发布验证。
5. **切换与多机安全：#58–#60。** 实现已定的绑定对账与切换语义、物理执行权租约与正常交权、双人强制改绑、板卡适配和多机部署。#58 中 AI 步骤对齐的范围仍依赖 Q25 裁决，不能从本路线推定为已确认；其已定的绑定切换切片可独立先行，#59/#60 不因此受阻。任一工位最多一台推理机拥有未过期物理执行权的约束，在数据库、用例和必要集成测试中共同成立；真实板卡、现场时间同步和容量属于后续验证。

Q25（AI 建模板范围）与 Q36（备份恢复）仍是 §四的待确认项，本路线不裁决它们。只有当某个实施任务的验收确实直接依赖其中一项时，才在该票上保留实际阻塞；Q36 的运维交付决策不阻塞可独立编码的软件。硬件门禁同样不阻塞无硬件依赖的代码实现。

### 8.3 发布与现场验证进度

旧路线 P1–P12 的完整条款保留在 §九。软件实现按 §8.2 推进，测试策略遵循 [`repository-verification.md`](repository-verification.md)；全面系统验证与目标环境证据由 [#1](https://github.com/cybest993-xx/nvsop/issues/1) 的验证清单逐项关联，验证任务依赖所需的软件实现，不反向成为无硬件依赖软件的开工条件。

没有真实硬件时可先完成 CPU 契约和故障逻辑，但不得把它写成硬件门禁已通过。TimescaleDB 等真实基础设施上的必要事务、迁移与数据行为验证仍随实施任务完成；后置的是完整运行链路、规模与现场证据。Q25/Q36 相关验证先保留未决标记，不把建议当成验收承诺。

### 8.4 本轮退出与未拆阶段

“软件实施退出”要求范围内任务及为其补出的必要依赖任务，均满足 §8.1 软件实施退出条件；未决范围不能默认为完成。它不等于全量验证或目标环境发布验收，也不关闭 #1。只有软件进度与全量集成、发布/现场验证进度都达到最终验收，#1 才能关闭。此分期策略适用于本轮 MVP；后续迭代若要延后验证，须重新确认交付分期。阶段 4 仍未拆出、未纳入本轮，不因本次顺序调整而新增产品范围。

## 九、验收门禁

本节的原始验收要求全部保留。软件阶段可以用合成数据、契约回放或 seam 替身证明可编码的业务契约，但不能替代真实设备、GPU、现场、多机容量或长稳验证；后置项必须留在开放关联任务中。测试选择、最小必要红/绿证据、证据复用与审查阻塞条件统一遵循 [`repository-verification.md`](repository-verification.md)；现有适用 CI 与发布门禁保持不变。

**实现任务关闭前的必要证据**：完成 [`repository-verification.md`](repository-verification.md) 要求的证据及该任务承担的验收验证。全量跨模块端到端、组合故障、长稳、规模性能和现场硬件证据按本节相应类别后置，但不取消原要求。

**实现与发布验证的原始追踪条目**：保留旧路线 P1–P12 的完整条款，软件部分按 §8.2 实现、后置验证按 §8.3 追踪，不把整个条目移到后期而延迟其中的软件能力。P11 的 AI 步骤对齐范围仍以 Q25 裁决为前提；保留原条目不表示本次已选择 Q25 的任何方案。

- **P1** 用本地官方数据训 DDM（单卡 resnet50，产出真实 checkpoint）。
- **P2** 起推理服务：真实 DDM 权重 + 公开 `Cosmos-Reason2-2B`，含该处改造与 supervisor 内的判定核心，用真实视频打通 `actions.json` → DDM 分段 → VLM → SSE → 判定全链路。
- **P3** 录制真实 chunk 流与流健康事件序列作为集成测试夹具（真实数据回放，非 mock）。
- **P4** GPU 门禁：按 §5.6 两类起点分别计量至 Web 渲染；同时验证**每后端常驻显存开销**（§5.10）、DDM-only / VLM-only / 全链路显存、断流重连与 OOM 故障注入、**N 后端 × 1 路**真实并发、72h 稳定性、**单调钟跨进程可比**（§2.13 登记的前提，一次读数比对即可）。
- **P5** **录像压缩实测**（§5.19）：在目标子码流上扫 CRF 定默认档、测 NVENC 与推理的实际争用、验证压缩任务限速与让路，据此复算 §5.5 容量表并确定可支持的保留期上限。
- **P6** 中心不可达演练：拔中心网线，验证判定、处置、锁存、本地排队继续；恢复后对账不重复处置、不丢证据。
- **P7** 完整 SOP 实例生命周期接真实流（含 IO 物理边界与空闲超时闭合）。
- **P8** 违规记录 + 5 种处置动作 + 证据切片（锚点 + 可配置前后余量，§5.20）+ 人工复核留痕闭环。
- **P9** 看板 SSE 与上报镜像（`monitor` 模块持久化启用 TimescaleDB，同时启用记录的原生压缩，§5.19）。
- **P10** **数据管理**（§5.19、§5.20）：`retention` 模块策略配置与回收任务、三类判定的证据保留、变更影响估算与引用保护、磁盘水位告警；录像压缩归档任务（含与判定争用的实测门禁）；**再切片委托命令**与复核界面上的可再切片截止时刻。
- **P11** 步骤对齐（时间码）+ 绑定对账与切换语义。
- **P12** 多机部署 + **`execution` 模块的交权握手、强制改绑双人确认与物理执行租约**（§5.17）、**板卡连接器适配器**（产线级联锁，第二个适配器验证能力声明这层抽象成立）、时间同步监控、多路扩展验证。

**发布退出门禁**：若单路 VLM 持续 backlog，立即降 VLM 为低频/旁路能力，重新评估产品承诺。

**正确性**：

- **返工序列不得误报**（§2.2 的 `1,2,3,2,4,5` 判通过）——这是本产品与基座原样行为的分水岭；
- 注入断流 / 丢帧 / 推理超时 / 时间戳跳变 / 点位断线 / 重连后时间轴归零时，系统不得输出错误的不通过；
- **闭合前有效性门生效**：断流期间触发空闲超时闭合时输出不可判定 + `STREAM_LOST`，不进入漏步集合比对；
- 漏步在实例闭合时立即报出（不等下一遍）；顺序型模板跳号即报；
- 每个不通过可追溯到模板版本、推理机自报模型标识、观测与证据；
- 模板切换期间旧实例不污染新版本；
- **未配置任何连接器的工位与配置了连接器的工位走同一套判定代码路径**（无 `if 配了连接器` 分支）；
- **工位运行参数生效值正确**：跟随模板的工位取当前绑定版本默认值，自定义的工位取自己那组且绑定新版本后不被默认值覆盖（§5.3）；
- **点位角色校验在绑定时生效**：把能力声明不足以承担该角色的点位声明为开始/结束信号时，绑定失败并给出具体原因，而不是在现场表现为不可判定（§5.8）；
- **未知原因码不致盲**：前端遇到映射表外的原因码时显示原始码 + 通用提示，其余信息照常显示，不空白、不丢弃该条判定（§5.2）。

**多机安全**（`execution`，§5.17）：任一工位在任一时刻最多一台推理机持有未过期物理执行权；交权握手未确认前新机不得写该工位输出点位；强制改绑必须记录两名确认人；租约过期后该机停止写点位且界面显式标注物理防错已失效。

**数据保留与压缩**（§5.19）：**所有保留时长与窗口均可配置，回收与切片代码路径无时间字面量**（机械检查保证）；配置校验拒绝非法值（0、负数、明细保留期短于压缩起始年龄、再切片期望超过录像滚动窗口）；"永久"与"未设置"在界面上可区分；三个判定类别各自的保留时长独立生效，挂有已锁存违规的实例按不通过类保留；缩短保留期只对将来生效且提交前显示影响估算；**仍被开放违规、在审复核或未结案实例引用的数据不被删除**（回收任务须报跳过计数与原因）；上报队列与证据队列不因空间回收而删除；磁盘水位越阈值时该路进不可判定并告警，不静默写失败。录像压缩须验证：**压缩任务运行期间判定链路的 p99 与超预算计数不劣化**（NVENC 与推理的实际争用在目标 GPU 上实测，不假设互不影响）；重编码产物校验通过后才删原分段，校验失败保留原文件并告警；**扫一组 CRF 定档**——取复核可用性开始劣化前的那一档为默认值，据此复算 §5.5 容量表；压缩后分段仍可支撑人工复核判断与再切片（由人判断，不用客观指标代替）；证据默认不重编码，其 sha256 与上传时一致。

**证据与复核**（§5.20）：片段窗口的必需跨度不被余量配置截断（取并集）；再切片不改锚点、追加不覆盖、标注窗口参数与素材代次；**界面显示可再切片截止时刻**，过期后按钮置灰并说明原因；素材已过滚动窗口的再切片命令以明确原因失败结案，不静默丢弃；归档压缩后的分段再切片产物**可在复核界面直接播放**（§5.19 约束 2）；复核结论指向具体哪一条证据。

**自治性**：切断中心—推理机网络后，判定、违规锁存、处置（含写输出点位）、证据切片、预览全部继续；恢复后上报对账幂等，处置不重复执行，证据不丢失；不兼容版本显式告警拒绝接入，不静默降级。

**性能**：按 §5.6 两类起点分别报告 p50/p95/p99、最大值和超预算计数；每个成功实时结果必须 ≤ 500 ms，测试窗口内超预算结果为零。拆分 DeepStream/chunk、DDM、VLM、判定核心、supervisor、上报、中心 SSE 和 Web 渲染耗时。长流 chunk delay 不持续增长；预览不得反压判定；**外部信号到判定的延迟**单独报（轮询模式下须报轮询周期）。**每推理后端的常驻显存开销单列**（§5.10 容量公式的一项）。

**稳定性**：先 72h 再 7 天；记录 RSS、显存、句柄、队列深度、延迟趋势、时间锚定偏移漂移、**SQLite 本地状态增长与录像磁盘水位**（§5.5 容量公式）；覆盖容器重启、宿主重启、磁盘不足、相机重启、连接器掉线恢复、中心离线与恢复。

**安全**：所有管理 API 认证授权（含反代的标注 UI 与训练微服务）；模板版本 sha256 校验且推理机上报实际生效值；推理服务离线启动不访问公网；**凭据不出现在中心的任何导出物、日志或 API 响应中**（§5.12）；**拉取响应按请求方主机裁剪**——以主机 A 的身份拉取，响应中不出现任何仅属于主机 B 的标识（§5.15）；**写输出点位的动作全部产生诊断日志事件**（物理联锁属高影响操作），并记录操作人与目标点位。
