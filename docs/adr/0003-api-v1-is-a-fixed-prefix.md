# `/api/v1` 是固定前缀，不是版本轴

中心后台控制面路径固定以 `/api/v1` 开头，但**该前缀不是版本轴**：不会出现 `/api/v2`。契约只做向后兼容演进（加可选字段、加端点），破坏性变更走全客户端协同发布，而不是并行维护两个版本。

## Consequences

- OpenAPI 由 FastAPI 代码生成，导出到 `packages/contracts/openapi.json`，CI 校验重新生成后工作区干净。契约兼容性检查必须能让破坏性变更失败——删除路径或字段、新增必填字段、收窄类型都是失败项，因为没有 v2 可供旧客户端退守。
- **响应枚举加值不是破坏性变更，删值与改语义是。** 判定原因码集合会增长（solution-and-roadmap.md §5.2），而没有 v2 供旧前端退守，故代价转移到客户端：所有客户端必须对未知枚举值有兜底渲染——原因码显示原始码 + 通用提示，不显示空白、不显示"未知错误"、不丢弃该条记录。兜底不成立时，这条豁免也就不成立。请求枚举加值同理可容忍，因为旧客户端不会发送新值。
- 单工厂内网、前后端同一交付物，协同发布成本低；并行版本的长期维护成本远高于收益。
- 推理机上的边缘运行时与可下载部署包是可能非同步升级的客户端。它们不靠 URL 版本兼容，而靠启动时的版本握手：中心报告兼容性，不兼容即拒绝接入并显式告警，不静默降级运行。
