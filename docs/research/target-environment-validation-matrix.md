# 目标硬件、设备与商业依赖验证矩阵

日期：2026-08-29  
适用目的地：[绘制 SOP 合规产品完整开工路线](https://github.com/cybest993-xx/nvsop/issues/1)  
基座基准：[`NVIDIA/sop-monitoring-blueprints@69352021c2aae0ba071acd2629f5cff224d14ca6`](https://github.com/NVIDIA/sop-monitoring-blueprints/tree/69352021c2aae0ba071acd2629f5cff224d14ca6)

## 结论

源码和公开规格足以提前准备测试工具、数据、制品清单和失败判据，但不能证明目标 RTX 4090 的实时路数、海康相机的编码/ISAPI 能力、掉流恢复、离线启动或模型商业可分发性。完整产品路线必须把这些结果视为**能力证据**，而不是实现阶段的附带检查。

验证分两步：

1. **环境准备**：拿到准确硬件/固件身份、合法制品和访问方式，生成可重复执行且不含秘密的验证包。
2. **目标环境门禁**：在真实 GPU、真实海康设备和断网环境执行本文矩阵，保存原始日志、指标、媒体探测结果、镜像/model digest 与结论。

未通过门禁不等于项目失败，而是触发已定义的降级或边界调整：VLM 改为低频/旁路、降低单节点路数、预览转码、ISAPI 改轮询、输出点位退出安全联锁、改用企业 GPU，或停止分发许可证不明的制品。

## 已知事实与不得外推的范围

- RTX 4090 官方规格为 24 GB GDDR6X、450 W TGP，官方建议整机电源 850 W；规格不能证明本工作负载容量。[NVIDIA RTX 4090 产品页](https://www.nvidia.com/en-us/geforce/graphics-cards/40-series/rtx-4090/)
- NVIDIA DeepStream 官方安装文档明确建议 24x7 dGPU 部署使用企业 GPU，并指出 gaming GPU 不为这类环境设计。因此 4090 可作为开发和受控试点基准，不能自动成为生产硬件承诺。[DeepStream 安装文档](https://docs.nvidia.com/metropolis/deepstream/dev-guide/text/DS_Installation.html)
- 基座 DDM 配置声明 `num_gpus: 1`，只证明训练程序支持单 GPU 配置；不证明该数据、batch、依赖版本在 4090 上的峰值显存、训练时长或准确率。[DDM 配置](https://github.com/NVIDIA/sop-monitoring-blueprints/blob/69352021c2aae0ba071acd2629f5cff224d14ca6/microservices/sop-training-bp/assets/config/ddm_train_config.yaml)
- 基座镜像基于 `nvcr.io/nvidia/deepstream:9.0-triton-multiarch`，构建期间还会安装依赖并 clone DDM；Basler Pylon SDK 是许可门控下载，模型不随仓库提供。在线构建成功不能证明客户内网可离线安装或可合法再分发。[推理 Dockerfile](https://github.com/NVIDIA/sop-monitoring-blueprints/blob/69352021c2aae0ba071acd2629f5cff224d14ca6/microservices/sop-inference-bp/docker/Docker.build)
- 基座真实并发 benchmark 尚未实现：`concurrent=True` 会退回顺序执行。因此多路结果必须由自有测试工具产生。[基座性能客户端](https://github.com/NVIDIA/sop-monitoring-blueprints/blob/69352021c2aae0ba071acd2629f5cff224d14ca6/microservices/sop-inference-bp/tests/api_client_perf.py#L584-L625)
- 海康能力随具体型号、固件、区域版本和通道而变化；在拿到型号与设备自报能力前，不把 `101/102`、告警 I/O、推送端点、B 帧开关或 ISAPI 请求体视为普遍能力。

## GPU 与推理门禁

### G1 原样启动与制品完整性

**前提**：真实 DDM checkpoint、已选定且许可可用的 VLM、固定镜像 digest。  
**步骤**：在干净目标主机加载固定制品；以非 dummy 模式启动；验证 `/v1/live`、`/v1/startup`、`/v1/ready`；用固定视频完成 DDM → VLM → checker。  
**通过**：无运行时下载；digest 与 manifest 相符；ready 只在模型就绪后成功；输出可重复并关联全部版本。  
**失败触发**：先修部署/制品，不开始容量测试；模型或镜像无法合法获得则从可交付基线移除。

### G2 模式分解

**步骤**：在相同输入与参数下分别测 DDM-only、VLM-only、完整链路，预热后记录 30 分钟。**另单列每个推理后端进程的常驻开销**（一份 DDM Triton 实例 + CUDA context），vLLM 作为共享端点单独计量。
**通过**：每种模式可单独归因；无 OOM/崩溃；记录峰值与稳态 GPU memory、RSS、CPU、功耗、温度；每后端常驻开销有明确数值，可用于容量公式。
**失败触发**：不能归因时不得用“总显存”做容量规划；优先补可观测性而非盲调参数。若每后端常驻开销过大以致一台机装不下所需模板数，则退化为"一台推理机一份模板"的部署约束（[`edge-autonomy.md`](../design/mechanisms/edge-autonomy.md) §5.10）。

### G3 单路实时性与积压

**步骤**：真实 RTSP 连续运行至少 2 小时；使用统一单调时钟关联最后必要源帧、DeepStream/DDM、chunk、VLM、SSE、本机 supervisor 内的判定核心、上报、中心 SSE 与 Web 渲染时间；记录各阶段 p50/p95/p99、最大值、超预算计数、队列深度和 chunk delay。**按结果类型分两类计量**：到达即判类起点为最后必要源帧，闭合类起点为闭合条件成立时刻（[`judgment-and-boundary.md`](../design/mechanisms/judgment-and-boundary.md) §5.6）。
**硬失败**：任一成功实时结果端到端延迟超过 500 ms；队列或 chunk delay 的长期趋势持续上升；任一未报告错误的 chunk 永久丢失；错误导致错误的“不通过”。
**决策触发**：先定位实际瓶颈并优先调整推理服务公开参数、模型与部署；REST/SSE 包装不是计算延迟的替代修复。仍不能达到 500 ms 时，该感知路径不得作为实时防错交付。不得通过删除时间锚、缩短测量区间或只报平均值规避门禁。

### G4 多推理后端真实并发与公平性

**步骤**：按真实部署形态运行——**每个推理后端进程配一路**，不使用基座顺序测试；1→2→4 个后端逐级运行，每档至少 2 小时。若某工位确实多相机共用一份模板，另测「单后端多路」作为对照档。
**通过**：无 OOM、死锁、进程重启或流饥饿；逐路都报告吞吐、延迟、丢帧、错误和恢复时间；队列不持续增长；**vLLM 作为共享端点在多后端并发下不成为瓶颈**。
**失败触发**：最后一个通过档位才是该配置的暂定上限，并至少保留一档安全余量；不得从 `VLLM_MAX_NUM_SEQS` 推导支持路数。

### G5 OOM、进程、宿主与中心不可达恢复

**步骤**：受控制造显存不足、杀掉推理容器、重启宿主，并在恢复后重放黄金视频。**另切断中心—推理机网络**，验证判定、处置、违规锁存与本地排队继续，恢复后对账。
**通过**：错误显式可见；活动 SOP 实例不会被静默续接为同一连续观测；恢复后版本/配置一致；不产生错误“不通过”。中心离线期间实时防错不中断；恢复后上报幂等、处置不重复执行、证据不丢失；不兼容版本显式告警拒绝接入而非静默降级。
**失败触发**：补齐本机 supervisor、状态对账或冷启动策略；无法保证安全语义前不得承诺无人值守恢复，也不得宣称中心离线自治。

### G6 稳定性与热设计

**步骤**：先 72 小时，再对候选生产硬件运行 7 天；混合真实流和周期性故障注入。  
**通过**：无未计划重启/OOM；RSS、显存、句柄、线程、队列、磁盘和延迟无单调泄漏趋势；无热降频导致的持续积压；错误“不通过”为零。  
**失败触发**：4090 仅保留为开发/受控试点，或降低路数；7x24 产品硬件转向经验证的 RTX PRO/企业 GPU。72 小时通过不能替代 7 天门禁。

## 海康 RTSP、预览与录像门禁

### C1 设备能力发现

**步骤**：记录型号/固件；从设备 Web/API 导出自报能力；枚举每个主/子码流实际 URL、认证方式、codec/profile/resolution/fps/bitrate/GOP/B 帧。  
**通过**：所有产品配置字段来自设备实际能力；错误凭证、不可达和不支持编码可区分。  
**失败触发**：界面按能力禁用选项；不把其他型号经验外推。

### C2 判定流连续性

**步骤**：分别执行首连失败、拔网线、丢包/抖动、RTSP 服务停止、相机重启；每次恢复至少观察 30 分钟。  
**通过**：独立探活记录最后帧、断开、重连、首个恢复帧；识别 PTS 回退/归零并重新锚定；不可观察区间不能产生错误“不通过”。  
**失败触发**：推理服务重连不足时扩大 pipeline 回调改造范围，或由本机 supervisor 重建请求；若仍无法可靠区分，向 NVIDIA 贡献最小流事件接口。

### C3 子码流浏览器预览

**步骤**：用真实子码流经 mediamtx 直通 WebRTC；在目标 Chrome/Edge 测单路与计划大屏路数的连续视频、首帧、玻璃到玻璃 p50/p95/p99、最大值、超预算计数、硬件解码、合成渲染帧率、内存、网络、边缘 CPU 和 72 小时稳定性。  
**通过**：每个成功预览样本的玻璃到玻璃延迟 ≤ 500 ms，测试窗口内超预算样本为零；无 B 帧兼容问题、持续花屏或断开；大屏连续视频达到目标路数，且预览拥塞不改变判定延迟。  
**失败触发**：先通过设备配置改变 codec/profile/GOP；仍失败才为该路启用转码，并重新测 CPU 容量。零转码不是无条件承诺。

### C4 录像、证据切片与磁盘故障

**步骤**：连续分段录像；跨分段执行 `ffmpeg -c copy` 切片；验证时间范围、可播放性和 sha256；注入磁盘不足/只读。**先按 `子码流码率 × 路数 × 7 天 × 1.3` 核算容量**（1 Mbps：裸容量单路 75.6 GB / 8 路 605 GB / 50 路 3.78 TB，含余量后按 ~98 GB / ~786 GB / ~4.9 TB 备料），再与实测增长对照。
**通过**：证据时间范围可追溯，上传失败可重试且不会误删本地唯一副本；磁盘故障不反压判定；实测增长与容量公式相符（偏差超 20% 须查明原因，不得直接调高公式）。
**失败触发**：调整分段/GOP、保留期或子码流码率；加入磁盘水位和保留策略后重测。

## 海康 ISAPI 与点位门禁

### I1 能力与认证

**步骤**：以具体型号/固件枚举 ISAPI 能力、输入/输出点位、HTTP(S)/Digest 认证、证书行为和权限；用最小权限账户测试。  
**通过**：产品只暴露设备确认支持的点位和方向；凭证不出现在 URL、日志或浏览器；读权限与写权限可分离。  
**失败触发**：无 I/O 的型号不提供连接器；无法最小授权时标记安全限制或改用独立 I/O 板卡。

### I2 输入采集模式和延迟

**步骤**：验证设备是否提供事件推送；若无则按多个轮询周期测 1,000 次按钮边沿，记录丢失、重复、乱序及设备时间与主机接收时间。  
**通过**：每条观测有来源时间、接收时间和质量；断线不会被解释成输入未触发。  
**决策触发**：轮询 p99 延迟与周期成为模板可配置时窗的下限；窄于该下限的规则禁止发布。若推送不稳定，回退轮询并明确能力。

### I3 输出安全与幂等

**步骤**：只在低压台架负载测试写入、重复命令、超时重试、断线、设备重启、中心后台重试和人工复位。  
**通过**：每次命令有幂等键、发起者、目标、期望状态、结果和审计；未知结果不自动重复危险动作；断电/重启状态符合风险分析。  
**失败触发**：海康输出只能用于声光/指示等非安全关键用途；停线或人员安全联锁改用经认证的 PLC/安全回路。软件产品不宣称摄像机继电器承担安全功能。

## 时间与网络门禁

### T1 时钟同步和流时间锚定

**步骤**：记录中心、推理机、相机时钟偏移；在 NTP 正常、失联、阶跃校时、漂移和主机重启条件下测外部信号与视频观测对齐。**另验证空闲时限按推理机主机单调钟度量而非 chunk 时间戳**：断流后 chunk 停止到达时，空闲超时须触发且闭合为不可判定。
**通过**：每个观测保留源时间、接收时间和单调时钟锚；偏移未知或超模板容差时输出“不可判定”，不输出错误“不通过”；断流期间的空闲超时闭合不进入漏步集合比对。
**失败触发**：依赖紧时窗外部信号的模板禁止发布；需要时升级为 PTP 或现场统一时源。

### T2 网络退化与断网自治

**步骤**：分别切断相机网络、中心—边缘网络和公网；恢复后检查缓冲、结构化事实对账、证据元数据/引用登记与本机证据文件保留，以及命令幂等。
**通过**：中心不可达时边缘按已确认版本继续；未确认的新版本不生效；恢复后不重复处置，不丢失已承诺证据。  
**失败触发**：在边缘持久化队列和 desired/reported 对账完成前，不承诺断网自治。

## 离线、安全与商业门禁

### L1 真离线安装与启动

**步骤**：在从未登录 NGC/Hugging Face 且拒绝所有公网出口的干净主机，从离线包安装、启动、重启和回滚；捕获 DNS/连接尝试。  
**通过**：安装与运行不访问公网；缺失制品在安装前由 manifest 明确报错；不静默下载；回滚恢复同一模板/model digest。  
**失败触发**：补齐镜像/模型/依赖 vendoring；门禁通过前“离线部署”不是产品能力。

### L2 SBOM、漏洞和许可证闭包

**步骤**：对源码、每层 OCI、OS 包、Python/npm、Pylon SDK、DDM/VLM 权重、测试/训练数据分别生成清单；人工确认许可证、模型条款和再分发范围。  
**通过**：每个交付制品有 owner、来源、版本/digest、许可证、notice 和再分发结论；无“unknown”；高危漏洞有修复或经签字的时限/缓解。  
**失败触发**：未知或禁止商业分发的模型/SDK 不进入交付包；改为客户自行下载也必须有明确安装和责任边界。本项是工程/法务输入，不构成法律意见。

### L3 凭证、日志和客户数据

**步骤**：扫描镜像、配置、日志、诊断包和浏览器网络请求；验证轮换与吊销。**特别检查中心生成的推理机配置骨架与任何可下载制品不含秘密**（凭据只在推理机本地，[ADR-0008](../adr/0008-credentials-stay-on-the-inference-host.md)）。
**通过**：没有相机密码、API key、数据库凭证、客户视频或模型权重进入 Git/日志/中心导出物；诊断包默认脱敏；秘密有轮换路径。
**失败触发**：修复信任边界后才能现场试点。

## 结果如何改变路线

| 结果 | 必须采取的路线变化 |
|---|---|
| 单路全链路持续积压 | VLM 降为低频/事件触发/旁路；实时步骤改用确定性 CV；重新描述销售承诺 |
| 每后端常驻开销过大，一机装不下所需模板数 | 退化为"一台推理机一份模板"的部署约束（[`edge-autonomy.md`](../design/mechanisms/edge-autonomy.md) §5.10 已按此设计留出退路，不改表结构） |
| 2 后端通过、4 后端失败 | 单节点支持值不得写 4；以低于 2 后端实测容量的保守配置交付，扩容靠节点 |
| 4090 72h/7d 热或稳定性失败 | 4090 只作开发/受控试点；生产矩阵转企业 GPU |
| 持续掉流不能可靠恢复或没有状态事件 | 扩大 pipeline 回调改造范围或由本机 supervisor 重建流；同时向 NVIDIA 贡献流事件接口以减少长期补丁负担 |
| 中心离线时现场不能自主判定或恢复后重复处置 | 补齐推理机本地持久化与幂等对账；未通过前不得宣称断网自治 |
| 子码流含不可关闭的 B 帧/浏览器不兼容 | 该型号预览走 CPU 转码并重新做容量规划，或从支持矩阵移除 |
| 录像磁盘容量不足 | 缩短保留期、降子码流码率或加盘；不得静默丢弃证据 |
| ISAPI 只有轮询 | 轮询 p99 决定最小可表达时窗；紧时窗规则禁止发布 |
| 摄像机无 I/O 或输出语义不安全 | 使用独立 I/O 板卡/PLC；摄像机不承担物理联锁 |
| 时钟偏移无法维持在模板容差内 | 相关判定只能不可判定；部署 PTP/统一时源后重测 |
| 离线启动发生外连 | 补齐离线包并重测，不得标称离线 |
| 模型/SDK 无商业再分发闭包 | 更换制品、改变为客户提供，或停止对应能力交付 |
